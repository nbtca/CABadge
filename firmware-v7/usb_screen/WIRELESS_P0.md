## 使用

1. 安装工作台预设 **CABadge v4 · 手机管理**，USB 连接后在“壁纸”页点击“允许手机管理”。也可以在板端“连接 → 手机管理”操作；实际屏幕未连接时点击电脑显示的圆屏。
2. STA 已联网：复制地址或扫码。手机须与板子同网且能互访。
3. 无可用 STA：用户点击“开启直连热点”，自动开启此次管理窗口；连接 `CABadge-xxxx`，输入显示的随机 WPA2 密码，再打开 `http://192.168.4.1/` 对应带授权码的入口。
4. 手机“壁纸”页选择 JPG/PNG，裁切、缩放、居中、上传；“设备”页查看真实状态并控制。电池只显示有效电压，亮度明确为预览亮度。
5. 关闭管理或等待 5 分钟，旧授权码失效。继续操作须在本地重新开启。关闭 Wi-Fi 或 BLE 同样撤销管理；因此网页不能在失去链路/授权后自行恢复权限。

热点每次重新开启生成新密码，重启默认关闭。原先 Wi-Fi 关闭时，临时热点关闭后恢复关闭；原先 STA 开启则回到 STA。AP+STA 采用现有 ESP-IDF 模式，具体手机兼容性与实板共存仍待验证。

## 权限与线程边界

- 只有设备 UI 或已连 USB 的明确操作能开启管理。USB 上传按钮是有线本地操作，不授予无线客户端权限。
- 单一短时管理会话，令牌为 16 随机字节（32 位十六进制）。HTTP 和 BLE 使用同一次设备授权；BLE 另绑定来访连接句柄，断开后清除该连接授权及其待处理命令。
- 令牌只在本地 UI/USB、URL fragment、HTTP 请求头或 GATT Session 写入中使用；不输出到普通日志，不保存到 NVS。连续五次错误认证暂停五秒，期限不因请求而延长。
- 网页静态文件可匿名取得；完整状态、控制、上传、取消、恢复默认均校验授权。关闭、超时、关无线、重启后旧令牌不能使用。
- HTTP 是本地明文管理；BLE 使用短时随机码握手，没有宣称安全配对、持久绑定或 LE 链路加密。这不提供公网管理或端到端加密。
- Wi-Fi/NimBLE 回调更新各自消息队列；管理模块只从 UI 线程读取服务状态和修改 LVGL。HTTP/GATT 只读取保护后的快照、提交命令，不调用 LVGL。
- 命令 202/ATT 写成功仅表示已进入处理队列。后续 `command_result` 表示分发结果；无线操作是否完成以 `connecting/scanning/connected/error` 为准，不把排队成功冒充连接成功。
- 上传与控制存在互斥检查，上传中控制返回 busy；提交锁只保护上传存储，UI 使用 try-lock。Flash 提交开始后取消返回 busy，已经提交的图片不能再承诺撤回；接收阶段取消、超时、CRC 错误不会替换旧壁纸。
- HTTP 接收在专用任务，30 秒总时限、5 秒单次读取时限；一次只接收一张图片，最多三个 HTTP socket。旧密码、完整日志、文件系统、OTA 和分区擦除都没有远程入口。

## HTTP 协议

请求头 `X-JX-Key: <32位授权码>`。浏览器须同源，不提供 CORS 放开；有 Origin 时须与 Host 的 HTTP origin 相同。页面与 API 使用 no-store / nosniff / no-referrer / CSP。所有控制体为 `application/octet-stream`。

| 方法与路径 | 内容 |
|---|---|
| GET `/` | 内置手机页面，无外网资源 |
| GET `/status` | 授权后的版本化 JSON：Wi-Fi、BLE、电池、显示设置、壁纸阶段及最后命令结果 |
| POST `/control` | 下表定义的二进制命令，最大 100 字节；成功排队返回 202 和命令 id |
| POST `/upload` | 固定 259200 字节 RGB565 little-endian；`X-JX-CRC` 为 8 位十六进制 CRC32 |
| POST `/reset` | 空体，原子提交默认壁纸记录 |
| POST `/cancel` | 空体，只取消 HTTP 接收，不取消 USB 上传或已开始的原子提交 |

不注册其他路径或方法。拒绝状态：403 未授权；400 长度/格式/参数错误；409 忙；408 接收超时/会话偏移错误；500 分配或存储失败。上传接口的 result：0 成功提交，1 忙，2 格式/CRC，3 存储，4 传输会话，6 未授权。应用到 UI 后快照 phase 才变为 4，网页此时显示“已保存并应用”。

壁纸 phase：JSON -1 / BLE 255 表示暂时无法取得快照，不推断具体阶段；0 空闲、1 接收、2 校验、3 提交、4 已应用、5 失败、6 取消、7 超时。USB 的旧 10～16 消息保留，新增消息 17（空 payload）切换本地管理窗口，回复原 WALL_INFO，增加 `authorized`、`remaining` 字段。

## BLE GATT 与命令

广播名和 GAP Device Name 为 **CABadge**，旧 `JXBadge-Test` 条目需重新扫描识别；只允许一条来访及一条主动连接。

服务 UUID `4e425443-4142-4000-8000-000000000001`：

| 特征（相同 UUID 前缀，末尾替换） | 属性 | 内容 |
|---|---|---|
| `000000000002` Status | read / notify | 授权后读取 20 字节状态；最多每 500 ms 检查变化，有变化才通知 |
| `000000000003` Control | write with response | 同 HTTP 二进制命令，最大 100 字节 |
| `000000000004` Session | write with response | 17 字节：`01` + 授权码对应的 16 个原始字节 |

nRF Connect 测试：本地开启管理 → 连接 CABadge → Session 选择 Hex 写入 `01` 紧接 32 个十六进制字符 → 读取 Status/开启通知 → 写 Control。默认 MTU 可容纳 Session、Status 和短命令；长 Wi-Fi 命令需协商 MTU 至少 103，否则不接受截断拼接。未授权读写返回 ATT 0x08，无效值 0x13，过长 0x0D，忙 0x81，服务失败 0x83。完整状态只向获授权的来访连接开放，主动连接的外设不会自动取得权限。

命令共同格式：`01 opcode payload`。控制结果（JSON `command_result`）：0 已分发、1 忙、2 参数无效、3 服务失败、4 未授权、5 待处理。

| opcode | payload |
|---|---|
| 1 Wi-Fi 开关 | 一字节 0/1 |
| 2 Wi-Fi 扫描 | 无 |
| 3 Wi-Fi 连接 | SSID 字节数、密码字节数、SSID UTF-8、密码 ASCII；SSID 1～32，密码 0 或 8～63 |
| 4 Wi-Fi 断开 | 无 |
| 5 BLE 开关 | 一字节 0/1 |
| 6 BLE 扫描 | 无 |
| 7 BLE 主动连接 | 地址类型 0/1 + 六字节小端地址；仅允许当前扫描列表内可连接项 |
| 8 BLE 断开 | 0 来访 / 1 主动 |
| 9 预览亮度 | 一字节 10～100 |
| 10 息屏 | 0 唤醒 / 1 息屏 |
| 11 减少动态 | 一字节 0/1 |

Status 20 字节布局（多字节小端）：

| 偏移 | 含义 |
|---|---|
| 0 | 协议 1 |
| 1 | Wi-Fi bits 0～4：开启/扫描/连接中/已连接/热点 |
| 2 | BLE bits 0～5：开启/广播/扫描/连接中/来访/主动 |
| 3 | 预览亮度 |
| 4 | bits 0～2：息屏/减少动态/电压有效 |
| 5～6 | mV，只有电压有效位为 1 才使用 |
| 7 | 有符号 RSSI，-127 为未知 |
| 8 | 壁纸 phase |
| 9 | 最后命令 result |
| 10～13 | 命令 id |
| 14～15 | 管理窗口剩余秒 |
| 16～17 | BLE / Wi-Fi 错误码低 8 位；完整错误见 HTTP JSON |
| 18～19 | 固件主/次版本；v4 为 4/0，当前 v5 为 5/0 |

## 验证与待测边界

构建/软件结果见发布目录 `software-validation.json`。测试明确分层：纯 C 的协议和存储；包含生产 `management.c` / `wallpaper_service.c` 的宿主测试（替代 ESP I/O、时钟和任务调度）；真实 Edge 手机视口与本地 HTTP 替身；原生 Tk 与 LVGL 交互；ESP32 交叉编译。宿主测试不模拟 RF、NimBLE ATT 栈或真实多线程时序。

必须实测：手机同网/直连访问、实际 GATT 写读通知、关无线与过期撤销、USB/HTTP 互斥、断线/取消/重启保留、Wi-Fi/BLE 共存与长时间稳定性。当前没有新增这些实板通过证据，也没有自动烧录。

实体 LCD 仍需连接器恢复后验证亮屏、触摸方向/手势、真实背光电流及 QSPI 刷新。GPIO1 背光与 GPIO38 CHG_ALLOW 保持 LOW。USB 帧率不作为 LCD 性能结论。

本轮不做 GIF/视频、多图素材库、BLE 传图、原生手机 App、OTA、云端或完整板端 UI 重构；新增操作没有伪装成这些能力。
