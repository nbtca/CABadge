# 仓库维护整理范围

用户已批准 2026-10-28 结构审查中的八项建议，并要求完成后提供总结。

- 以公开 `80ebcf2` 为整理基线；原工作区的 7.9.25 / m1ngsama 与其他未提交资料保留在本地开发分支，不混入公开固件。
- 更新维护指引与架构入口；版本状态集中在 README / HANDOFF，不把旧描述当作当前状态。
- 发布必须记录实际源码提交与配置；既有固件标签、附件和工作台正式默认不改写。
- F 盘存放规则保留。构建工具统一使用可覆盖的 `CABADGE_BUILD_ROOT`，默认 `F:\CABadgeBuild`；不再依赖旧 firmware 源码目录里的环境。
- 固件复制清单与指纹清单合并。通用名片保持 Egger，定制姓名通过显式构建参数覆盖。
- 新增小型发布工具，检查实际 R2 料件、清单、归档和固件源码身份；生成可复核的交付包。
- 将宿主测试移至 firmware-v7/tests/host，仓库检查移至 tools/repository，设计/架构移至 docs/architecture，并修复消费者与链接。
- 增加离线 CI 与相应忽略例外。依赖现有 Python/Git/PowerShell 工具，不新增通用发布框架。
- 两个现有 CAD ZIP 以原字节发布到专用 GitHub Release，更新首选下载入口；原路径保留兼容，后续大型包优先走 Release 附件，不重写 Git 历史。
- PCB、KiCad 库、EDA 重画工程、V1 归档和冻结制造集合保持字节；不重新核对 BOM，不连接或烧录设备，不改写实测结论。

验收：仓库完整性与链接、发布失败用例、迁移后的宿主检查、真实板端编译、GitHub CI、线上文件指纹、原工作区文件指纹和保护集合比较。构建不代表实体验收。
